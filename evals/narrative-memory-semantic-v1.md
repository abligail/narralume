# 章节记忆语义验收 v1

本组是六类真实正文的冻结夹具，供实际弧复盘与实际滚动规划同组对照。它不宣称覆盖完整长篇，也不以引用格式通过代替语义正确。正文、版本、hash、已有指南针、作者方向和实体目录只读提取自保存的实验副本；没有为了判据改写原正文或合成错误阶段记录。

## 输入与审计边界

`narrative-memory-semantic-v1.json` 根为 `{ version, description, extraction, cases }`。每例只有创作输入进入 production worker：`language`、`scope`、`compass`、`authorIntent`、`entities`、`chapters` 的正文及实际存量摘要/summaryPoints。章节 `inScope` 标明本阶段，历史章仅用于回查，不挪作本阶段新发生的事件。runner 按每例的夹具顺序将提供的章节连续编号为1、2……；生产prompt不保留原章号。原章号仅存在 `source.chapterNumber` 审计信息中，中间未提供的章不合成正文。

`id`、`title`、`source`、`compassSource`、`description`、`extraction` 和整个 `rubric` 只用于实验标识、复核与评分，不得作为给模型的验收答案或提示。尤其不得将 `expected`、`forbidden`、`allowed`、`knowledgeBoundaries`、`notes`、`sourceEvidence` 注入模型。模型看到的是既有作品材料，不能看到案例标题暗示的答案。

每章 `source` 包含原数据库相对路径、projectId、documentId、versionId、contentHash 和 chapterNumber。正文保持原字符串；hash 为 UTF-8 SHA-256。`sourceEvidence` 使用现有 `ParagraphLocator`，段号从1起算，位置为原字符串 UTF-16 offset，保存完整原段及版本/hash。这些段是人工定位辅助，模型仍按实际上下文编译结果获取完整章或合法历史片段。

指南针去掉归属新隔离项目所需的 projectId/version/updatedAt；其原版本、时间及投影 hash 保留在 `compassSource`。作者方向及实体来自同一个来源副本，未清理既有错误或把新事实手工写进旧记录。实际存量 summaryPoints 仅在匹配当前正文 hash 的真实记录存在时带入；原稿只有旧摘要时，不伪造 evidence-backed 要点。

原章号到夹具编号的映射依次为：人数14/15→1/2；回执4/5/6→1/2/3；交接15/17/18/19→1/2/3/4；抵达与信号17/18/19→1/2/3；机制13/15/17/18/19→1/2/3/4/5。以下判据引用原章号定位原文，实际输出引用应以稳定chapterId、版本及段号核对，不能把夹具显示章号与原章号差异误判为事实错误。既有指南针记录里的原章号没有改写，这是最小夹具的限制。

回执原指南针没有“韩渠已拿到”的合成错误记录，本例不声称检验强干扰抵抗。阿苇相关例保留真实世界线旧 `openPromises` 中“包括阿苇下落未定”。母女关系有真实实体苇娘的别名与描述支持，不能把它另立为待解关系。当前生产planner会收到实体目录，review不会；所选完整正文没有明确母女身份句。因此review将这段关系列未知时，应记录为这项判据的输入缺口，不能算已充分提供证据后的语义误读，也不能算完整通过。正文段落全部进入并不证明实体身份等所有判据输入充分。

信号例必须合读完整时间段：17章露娜P93先提出她敲，P102–103明确两下安全、一下示警，P104又有小柒回程敲两下的句子；18章明确远处听不到及孤立一声来源未知，手敲裤布不证明已送达；19章小柒近距离敲两下后露娜现身可作招呼。允许指出发送主体/距离措辞歧义，不设“只有露娜能敲”的假事实，不因出现“双方”二字直接判错。

机制例保留13章真正接通阵心后的停印效果，防止反向误判“从未验证任何机制”。19章P56视点叙述像肯定，露娜P62又说唯一且必停，而P74/P78仍要求去看是否还在、能否接。判定的是新地点、新对象的实证层级，不能用绝对词正则或把人物确信自动升级为客观保证。

## 执行与冻结

每例3次独立重复；每个重复的review与planner分别从相同冻结夹具新建独立阶段数据库，运行 actual review 与 actual rolling planner。planner不读取同一重复中新生成的review结果。基线共18个复盘和18个规划 worker；候选按同样输入、模型设置、重复数和预算再运行36个 worker。基线与候选共享数据文件 hash，记录源码 commit/build、模型代理标识、预算、输入/context receipt、结构尝试、repair、timeout、总耗时和最终产物。不得把旧 dist 结果记为新源码表现。

阶段隔离避免新复盘的偶然结果改变planner基线输入，复盘候选也不自动采纳。实际规划读取的夹具输入及其作者裁定/已有实体，按 runner 的固定公开流程记录。此夹具未复制全部历史裁定集合、全部章节/scene/state/review/canon关系，因此结果是固定生产 worker 的最小语义对照，不能称完整原生产项目复现。源实体/作者方向的补全只避免空目录导致重新提案，不能弥补这些限制。

`--resume`只在新attempt目录补缺失阶段，保留此前产物；执行报告与语义评分均选择每例每次每阶段最早有效完成的输出，不能用补跑的新review替换原来有效的review。有效完成同时要求最终输出及实际request对象的hash与阶段记录相符；请求证据缺失或改动的输出不能复用或算通过，原输出和执行成本仍保留。每份评分记录写明选择的产物路径及hash；额外调用、repair及失败成本均按全部attempt累计。中断时已有request但没有最终result的调用单列未完成，不冒充已完成或无成本。连接失败不改变判据，也不改模型配置补跑充当同组基线。

开始任何基线前固定 JSON 字节 hash，并在每个 run artifact 中记录。任何 JSON 编辑，包括非prompt rubric，均产生新 hash；若发现 oracle 错误，先暂停评分并记录变更，不把新旧判据偷偷合并。候选不得修改正文/摘要/旧指南针来迎合验收。

## 可复核语义判定

本批评分署名Codex，按人工可复核的标准逐例、逐重复审阅review与planner的完整最终产物；评分记录不表示有人类作者审批。可由另一代理独立二次审阅并记录分歧。检查observations、各长线progress/openPromises、recommendations、rationale、continuityRisks、章节计划和实体候选，不能只读正确的observations后忽略相反的建议。对每条发现保存原字段路径、原句、所用段/实体证据和简短理由。未实际采用的建议也属于可继续传播的输出，应评分；明确标为未来尝试的行动不作为已经发生的事件。

- `input-fail`：所需正文没有真正进模型、源版本/hash不符、oracle泄漏、旧build或不同预算等。不得将输入缺陷统计为模型语义错误，也不得算通过；保存 receipt 后修正实验再重做。
- `structural-fail`：production worker 未通过结构/引用校验或在既定重试上限内失败。单列失败次数，不能以最后一个repair结果掩盖成本。
- `semantic-fail`：任何最终字段满足该例的 forbidden，或明确违背必需事实/知识边界。真实引用不能豁免错误解释；须提供具体句子，人工判断语境与时间。
- `not-demonstrated`：没有错误，但整对 review/planner 未足以展示某项必需事实。例如从不提儿童人数，不能证明会正确数出五名。记为覆盖不足，不记作语义通过。
- `pass`：输入有效，生产流程完成，整对输出对该例 expected 有明确表现，且无 forbidden 或知识边界违反。review/planner分别记录每阶段语义失败及其路径；某阶段无错不等于该阶段已经展示全部必要事实。整对总判定采用任一失败优先，必需事实覆盖可在两个阶段输出中共同展示并单独记录。

允许措辞、知识边界及原稿歧义优先于字面匹配。独立复核存在争议时记录争议句及证据，暂列 `adjudication-needed`，不强行判通过或用判词正则替代语义。区分“将验证/她认为/听说”与“已证实/已做到”，也区分目的地与完成抵达；无需输出某个固定句式。

v1成功标准：候选六类各3次均为有效完成输入，零 `semantic-fail`，每类必需事实均有明确表现；`not-demonstrated`、结构失败、输入失败或未解决的人工争议不能被算通过。若只看到错误率下降但仍有失败，只能报告渐进改善，不宣称稳定验收成功。18组不能估计长篇无人干预可靠率；此组失败先据 receipt 区分系统输入问题与模型语义误读，再决定最小下一步。
